## 0. What is verified and what is not

Everything below is derived from excerpts quoted in `2026-07-frontend.md` and from `project_knowledge_search` hits on `public/portal/tokens.css` and `public/portal/shell.js`. **I do not have the working tree.** Every path, line number and current token value is therefore *indicative*, and Phase 0 of each session reconciles it against the real repo before changing anything. The backend-engineer standing rule applies: spec says an indicative name, check the real tree, use the real path, proceed.

Three things are asserted with high confidence because the audit measured them directly:

- `public/portal/tokens.css` is 21,070 bytes, declares 43 custom properties, and is loaded by **all 14** portal pages.
- `public/portal/` is 14 `.html`, 15 `.js`, 15 `.css`, plus `fonts/` (1 `.css` + 6 `.woff2`).
- `npm test` is `node --test --require ./tests/_support/testEnv.js tests/**/*.test.js` and returns **830 / 142 suites / fail 0**. It executes nothing in `web/`.

### 0.1 Correction to the frozen spec

The spec says *no custom property is renamed*. That is wrong for two properties and the error would have been silent and expensive.

The existing ramp uses `--teal-600: #0d6b63` and `--teal-700: #0f5f59` as **darker steps below** the base `--teal: #0f766e`. The v2 ramp uses the standard 50–900 convention where **`--teal-700` *is* the base** at `#0f766e`. Same two names, two incompatible conventions. Redefining `--teal-700` in place would silently repaint every existing consumer — `.nav__item--active` among them — with no compile error and no failing test.

**Resolution (D1):** the two existing names are re-pointed to intent-named properties, `--teal-hover` and `--teal-press`, and every consumer inside `public/portal/` is updated mechanically. Blast radius is exactly `public/portal/`, because each surface declares its own `:root` — `demo/shared.css` and `demo/styles.css` are unaffected by a change in `tokens.css`. Phase 0 proves that with a grep before the edit, not after.

Everything else in the spec's "nothing is renamed" claim holds: `--radius`, `--radius-sm`, `--radius-xs`, `--shadow`, `--shadow-sm`, `--teal-050`, `--accent`, `--s-1`…`--s-7` all survive as aliases.

### 0.2 Two claims from earlier turns that need correcting

**F-F008 is decided here, not closed here.** The brand decision is made — teal wins as one ramp, `#0f766e` is the light-ground step, `#14b8a6` is the ink-ground step. But closing the finding requires editing `web/app/globals.css`, which is outside all four granted buckets and outside `public/portal/`. That is a separate ~1h session. Batch 1 delivers the portal half and leaves the finding open.

**The command palette has no mockup.** The spec names three new components — truth strip, Verbatim panel, command palette — and Batch 1 drew the first two. The `⌘K` hint appears in the top bar on every artboard; the panel itself does not. It is a well-understood pattern with low design risk, so D2 implements it to spec and its DoD screenshot serves as the mockup after the fact. If you would rather approve a drawing first, cut it from D2 and it moves to Batch 2 — the hint stays either way, because a visible affordance for a feature that exists is not a placeholder.

**The test count is the signal.** Batch 1 changes no behaviour, so `npm test` should hold at 830 through D2, D4 and D5, move to 831 at D1 (the drift test), and move by at most one assertion at D3. **Any other movement means a session touched behaviour and must be stopped and explained.** That inverts the usual reading: here, a *changing* test count is the alarm.

**Per session, pasted into the issue:**
- the raw `tests N / fail 0` block
- the screenshots named in that session's DoD
- `git diff --stat` proving no file outside §1 was touched

**Batch acceptance, after D5.** Re-run the portal-v1 §11 criterion end to end on a fresh tenant: operator creates an owner account; the owner completes the wizard on a phone unaided in under 45 minutes; readiness reaches green; Go live; then edit a treatment price and confirm the Test page quotes the new price on the next message. The redesign is only successful if that run is *faster* than it was before. If it is slower, the sticky save bar or the table→card conversions are wrong and D5 reopens.
